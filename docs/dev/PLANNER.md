> **Input:** a Norwegian organisation number → **Output:** an evidence-backed, refreshable company profile

## 0. TL;DR (read this first)

1. **The deadline is very close.** Revised commit hashes close on **Sun 18 Oct 2026**. Round 1 closes **Wed 21 Oct 2026**. The scored commit has to contain the agent **and** the showcase generator, because UX is scored. Everything below is sized to fit a **~2.5-day build window**.
2. **Nobody has qualified yet.** As of the 5 Oct board review there were 37 submissions, 28 assessed, **0 qualified**, and the top score was **60.80/100**. The bar is **≥65**. A clean entry that qualifies has a real shot at the prize pool.
3. **Precision is pass/fail.** A single *material wrong-company publication* or a *fabricated financial value* disqualifies the entry. A search snippet (not confirmed on the repo page) reported one competitor scoring 74.67 but being blocked for publishing wrong-company websites. **Rule: when in doubt, return `ambiguous` or `not_available`.**
4. **Execution is pass/fail.** Each input needs exactly one terminal envelope, and runs must finish within 45 min, 2,000 outbound requests and $10. A run with a missing row or a timeout is not scored at all.
5. **How to win:** take the official registry data at 100% (cheap and certain), add an **identity-gated website** as the hub for most external facts, then add jobs, dated activity, social profiles and announcements. On top of that, add **idempotent refresh with typed diffs**, a **cited company brief**, and a **static showcase site generated by the same run command**.
6. **Fork the official starter kit** rather than starting from scratch. It already provides envelopes, registry, financials, roles, subunits, evidence hashing, checkpoint/resume and refresh replay. Our time goes into coverage, the identity gate, synthesis and UX.

## 2. Winning strategy (score analysis)

| Score bucket | What earns it | Our play | Priority |
|---|---|---|---|
| **Coverage (35–50)** | 70% company recall + 30% claim recall per field family, measured against a pooled set built from all entrants and Builderr crawlers | Reach ~100% on the registry families; push coverage of the **verified website** (the hub for social, contact, news and description); add jobs and announcements. The starter's proxy scorer weights **external footprint at 55/100**, so this is where we pull ahead. | 🔴 P0 |
| **Precision + evidence (30)** | Right company, valid source span, valid dates | Strict identity gate; every claim carries a span and hash; typed validators; a hand audit before every submission | 🔴 P0 (gate) |
| **Update / refresh (12–20)** | Idempotent rerun, typed changes, prior evidence kept, no false changes | `--previous` input; stable claim keys; diff engine; carry forward on failure | 🔴 P0 |
| **Synthesis (10–12)** | Explains what the company does, what changed and what is unknown, with sources | Deterministic cited brief + optional LLM polish under a citation guard | 🟠 P1 |
| **UX (5–8)** | Find, compare and verify on desktop and mobile | Static showcase site generated by the run command | 🟠 P1 |

**Non-negotiable gates (the run fails without these):**
- One envelope per input, even on a crash. Use a global watchdog plus a per-company try/except that emits a `failed` envelope.
- Finish under the time and request budget. Use the budget allocator and degrade gracefully.
- Zero wrong-company publications. Prefer `ambiguous`.
- Financials come only from Regnskapsregisteret / official filings, copied verbatim and never computed or imputed. Derived ratios are labelled `derived` and reference their inputs.

## 4. Backend plan

### 4.1 Tech stack
- **Python 3.12 + `uv`** with a pinned `uv.lock`. The install step is `uv sync --frozen`.
- `httpx` (async, HTTP/2), `anyio`, per-host semaphores and token buckets.
- Parsing: `selectolax` or `lxml`, `extruct` (JSON-LD/microdata/OpenGraph), `trafilatura` (clean text).
- Identity: `rapidfuzz`, `tldextract`, `phonenumbers`.
- Models and validation: `pydantic` v2. Storage: SQLite (snapshots + claim history) or DuckDB.
- Showcase: `jinja2`. The static site is emitted with inlined JS, so the evaluation path needs no Node.
- Optional LLM: Anthropic API (`claude-haiku-5-5`) through the `ANTHROPIC_API_KEY` env var, **off by default**. The agent must reach full score paths without it.
- Tests: `pytest`, with fixtures recorded from real responses.

### 4.4 Identity gate (most important module)

A website or profile is **published as exact** only if one of these proofs holds:
1. **Orgnr proof:** the exact 9-digit orgnr appears on a fetched page of the domain. Accept formats like `923 609 016`, `923609016`, `NO 923 609 016 MVA` and `Org.nr:`, and check the mod-11 checksum. **AND** no *other* orgnr appears as the site owner.
2. **Contact proof:** the normalized legal name (strip AS/ASA/ANS, æøå folding) matches **and** (the registry phone **or** street + postcode) is present on the page **and** the domain is `.no` or matches the registry email domain.
3. **Registry declaration + corroboration:** the registry `hjemmeside` resolves (after redirects) to a live site **and** the name or address corroborates. A site with only the registry link and nothing corroborating → `ambiguous` (or publish as `registry_declared` with lower confidence, if Discord confirms that is acceptable).

**Hard rejects (→ `ambiguous` + reason logged):**
- The site shows a **different** orgnr (parent, brand, franchise, accountant). Record a `related_entity` claim instead.
- Parked or for-sale domains, site-builder templates, directories, social networks as a "website", and cross-domain redirects to a different brand.
- Generic names (e.g. "Bygg AS") without orgnr proof.

**Candidate generation order:** registry `hjemmeside` → registry email domain (exclude free-mail domains such as gmail, hotmail, online.no, outlook) → Wikidata P856 → slug guesses (`{name}.no`, `{name-with-dashes}.no`) checked with a DNS lookup first → search API (optional).

**Audit:** every gate decision is stored with `identity_reason` + `proof_snippet`. Before each submission, hand-audit **≥100 published websites** for 0 wrong and commit the audit file (`reports/identity-audit.md`). It is also strong showcase material.

### 4.5 Claims and evidence model (envelope)

This extends the starter's `OUTPUT_CONTRACT.md`. Keep its field names so the evaluator's parser still works.

```json
{
  "organisation_number": "923609016",
  "run": {"run_id": "...", "started_at": "...", "completed_at": "...", "terminal_status": "completed", "agent_version": "git-sha"},
  "identity": {"legal_name": "...", "legal_form": "AS", "status": {"bankrupt": false, "liquidation": false}, "public_brand": null},
  "availability": {
    "financials": "available", "leadership": "available", "locations": "available",
    "website": "ambiguous", "social_profiles": "not_available", "jobs": "available",
    "activity": "available", "group": "not_applicable"
  },
  "claims": [
    {"id": "c-…", "field": "revenue", "family": "financials", "value": 12345000, "unit": "NOK",
     "period": {"from": "2025-01-01", "to": "2025-12-31"}, "availability": "available",
     "confidence": 1.0, "method": "api_field:resultatregnskapResultat.driftsresultat.driftsinntekter.sumDriftsinntekter",
     "evidence_ids": ["ev-…"], "derived": false}
  ],
  "evidence": [
    {"id": "ev-…", "source_url": "https://data.brreg.no/regnskapsregisteret/regnskap/923609016",
     "source_class": "official_registry", "retrieved_at": "...", "content_sha256": "...",
     "claim_span": "\"sumDriftsinntekter\": 12345000", "license": "NLOD-2.0", "identity_reason": "orgnr_key"}
  ],
  "brief": {"sentences": [{"text": "...", "claim_ids": ["c-1", "c-4"]}], "unknowns": [{"family": "website", "reason": "no candidate passed identity gate"}]},
  "changes": [{"type": "new_role", "field": "ceo", "previous": "...", "current": "...", "evidence_ids": ["..."], "detected_at": "..."}],
  "errors": [],
  "operations": {"requests": 11, "runtime_ms": 8120, "third_party_cost_usd": 0.0}
}
```

- **Claim ID** = `sha256(org|field|normalized_value|period)`. This keeps IDs stable across reruns, which is what makes reruns idempotent.
- **Evidence ID** = `sha256(source_url|content_sha256)`, so an identical snapshot produces an identical ID.

### 4.6 Budget allocator + watchdog (execution safety)
- Read N from the batch file and derive per-phase budgets: `requests_total = 2000 × 0.9` safety margin, `deadline = start + 40 min`.
- **Phases (priority order):** P1 registry + accounts for all companies → P2 roles/subunits/announcements → P3 website gate for companies with a registry site → P4 website discovery for the rest → P5 enrichment (news, RSS, careers, Wikidata).
- Each phase checks the remaining budget. If it runs out, later phases mark their families as `not_available` with `reason: budget_exhausted`, not `failed`. Confirm the preferred state on Discord.
- **Watchdog:** at T+42 min, cancel tasks, flush every company's envelope (partial claims kept, unfinished families → `failed` with reason), write the run report and exit 0.
- **Checkpoint:** stream envelopes to JSONL as each company finishes, and add `--resume`.
- Count **every** outbound HTTP request in one counter (including redirects and robots.txt), and write the count to the run report.

### 4.7 Refresh (worth up to 20 points)
- `--previous out/profiles.jsonl` (or the snapshot DB) is an optional input. Without it the run is a first-run baseline.
- Diff on stable claim keys. Change types: `new_value`, `changed_value`, `removed_value`, `new_role`, `ended_role`, `new_filing`, `new_location`, `closed_location`, `new_job`, `closed_job`, `new_announcement`, `status_change`, `website_change`.
- **Idempotent:** the same source snapshot produces zero changes and no duplicate evidence. Test this in CI.
- **Failed fetch ≠ removal:** carry the last supported value forward with `stale_since`, mark the family `not_compared` in changes, and keep the prior evidence.
- Preserve history: the snapshot store is append-only, and old evidence IDs stay resolvable.
- Prove it: ship `reports/refresh-replay.json` (two runs on the same 100 companies, plus a mutated-fixture run showing the expected changes).

### 4.8 Synthesis (cited brief)
- **Deterministic first.** Templates fill from claims only:
  - *What it does:* NACE text + verified self-description (labelled "company's own description")
  - *Size:* employees (registry, dated) + revenue (period)
  - *Health signals:* result trend if ≥2 years, status flags, announcements
  - *Footprint:* website, socials, active jobs
  - *What changed* (from the diff)
  - *Unknowns:* each family not `available`, with its reason
- Every sentence lists `claim_ids`, and the showcase renders them as clickable citations.
- **Optional LLM polish** (off by default, flag `--llm`): Haiku rewrites the brief, then a validator checks that every number, date and name in the output exists in the cited claims. Any sentence that fails is dropped and the deterministic sentence is kept. The cost cap is enforced in code. No LLM ever decides identity or invents fields.

## 5. Frontend plan (showcase UI, scored for UX)

### 5.1 Principle
**"Every fact is one tap from its proof."** Judges score whether users can *find, compare and verify* on desktop and mobile, so the UI should make verification the core interaction.

### 5.2 Delivery format
- **Primary:** `--showcase out/site` writes a **self-contained static site** (HTML + inline CSS/JS + JSON data shards) from the same run. It needs no Node, works offline, is reproducible from the pinned commit, and can be hosted anywhere (GitHub Pages, Cloudflare Pages).
- **Secondary (demo only):** `uv run signalpost serve` runs a small FastAPI app with a **Live Lookup** page. Enter any orgnr and watch the agent work (SSE stream of steps: registry → accounts → candidates → identity gate verdicts → profile). This is the "wow" for the video and gallery.

### 5.3 Pages / views

| View | Contents | Key interactions |
|---|---|---|
| **Run dashboard** (home) | Hero search; KPI tiles (companies, % with each family, wrong-company = 0, requests, runtime, cost); coverage bar chart per family; state distribution | Search by orgnr or name; click a family → filtered explorer |
| **Explorer** | Virtualized table of all companies: name, orgnr, form, municipality, NACE, revenue, employees, website ✓/?, jobs count, last change | Filters (state per family, county, industry, has website, has jobs, changed since); sort; CSV export |
| **Company profile** | Sticky header (name, orgnr copy button, form, status badges, last refreshed). The **cited brief** at the top. Sections mirror the 7 required profile sections. Availability chip on every section. **Unknowns** panel. | Hover/tap a citation → highlights the claim; tap a claim → evidence drawer |
| **Evidence drawer** (bottom sheet on mobile) | Source URL (opens), source class, retrieved_at, reporting period, SHA-256 (short + copy), claim span with highlight, extraction method, identity reason | "Open source", "Copy citation" |
| **Financials** | Statement table by year, sparkline for revenue/result, derived ratios labelled "derived from …" | Toggle years; values shown with currency and period |
| **Changes** | Per-company timeline + global changes feed (typed icons: new role, filing, job, address…) | Filter by change type, date |
| **Compare** | 2–4 companies side-by-side: identity, size, financials, footprint, states | Add from explorer/profile; shareable URL `#compare=org1,org2` |
| **Method & sources** | How identity is verified, sources + licenses, budgets, identity-audit results | — |
| **Live lookup** (serve mode) | Step log with gate decisions, live profile assembly | Enter an orgnr |

### 5.4 Design system
- Nordic, clean look: neutral greys, one accent (fjord blue), semantic state colours with icons (not colour alone): available ✓ green, not_available — grey, ambiguous ? amber, blocked ⛔ red-orange, failed ✕ red, not_applicable ∅ slate.
- Inter or system font stack; tabular numerals for money; Norwegian number formatting (`12 345 000 kr`) with an EN/NO toggle.
- Light and dark themes; WCAG AA contrast; keyboard navigable; tap targets ≥44px.
- Mobile: sections become accordions, the evidence drawer becomes a bottom sheet, compare becomes swipeable cards.
- Performance: a search index JSON (orgnr, name, municipality, NACE, flags) of ~150 KB for 1,000 companies, plus per-company JSON loaded on demand.

### 5.5 Tech
- Jinja2 templates + vanilla JS modules (or Preact + HTM bundled inline with no build step). No framework build in the evaluation path.
- If time allows after 18 Oct, a separate **demo repo** can host a more polished hosted gallery (e.g. Vite + React). It must not change the scored commit.

## 6. How to showcase the agent (best approach)

Ranked by impact:

1. **The generated showcase site, hosted.** Run 1,000 random companies from the universe, publish `out/site` to GitHub Pages, and put the link at the top of the README and in the email. Judges can open any company and verify any fact in one click.

The README does not need to say it, but this is exactly the failure that blocked other entries.
3. **Refresh demo.** Show two runs side by side, with a changes feed showing a real new filing, role change or job, plus "rerun = 0 false changes".
4. **A 2–3 minute video** (Loom/YouTube, unlisted):
   1. The problem (10s)
   2. The one-command run with a live terminal (20s)
   3. The dashboard (20s)
   4. One company profile → tap a fact → evidence (40s)
   5. An identity-gate rejection example (20s)
   6. The refresh diff (20s)
   7. Live lookup of a new orgnr (30s)
   8. Cost/requests/time stats (10s)
5. **README as a landing page:** hero screenshot/GIF, a "Run it" block, a metrics table (coverage per family, precision audit, p95 runtime, requests, $ cost), an architecture diagram, and a sources/licenses table.
6. **Community vote + certificate:** post on LinkedIn by **18 Oct** (the last community award date) with the video and hosted link. Once qualified, claim the Builderr profile and certificate.

## 8. Testing & local evaluation
- **Contract tests:** N in → N envelopes; valid states only; no zero-for-missing; every `available` claim has evidence with a hash and a span.
- **Identity gate tests:** fixtures for orgnr formats, a parent-orgnr page, a franchise, a parked domain, a same-name company, and redirects to a different brand.
- **Refresh tests:** identical rerun → 0 changes; a mutated fixture produces the expected typed changes; a failed fetch carries values forward.
- **Budget tests:** a simulated slow host still produces all envelopes before the deadline.
- **Clean-machine test:** in a fresh dir, `git clone` → `uv sync --frozen` → the one command on 100 companies. Run it in GitHub Actions on every push.
- **Local scorer:** the starter's `score_competition_v3.py` plus our own per-family coverage and precision on a hand-labelled gold set (dev/val split, no overlapping orgs or hosts).
- **Hand audit:** before *each* submission, review a random 100 published websites plus all social links.

## 10. Risk register

| Risk | Impact | Mitigation |
|---|---|---|
| Wrong-company website/social published | **Disqualifies** | Strict gate, hand audit, prefer `ambiguous`, reject different-orgnr pages |
| Missing envelope / timeout | Run not scored (0 for the day) | Watchdog at 42 min, per-company try/except, streaming writes, CI clean-machine run |
| Request cap exceeded | Run invalid | Single counter including redirects/robots, 10% margin, phased allocator |
| Financial value wrong or fabricated | **Disqualifies** | Verbatim API fields only, period attached, never infer, derived values labelled |
| Brreg regnskap 30/min limit on history | Slow runs | History only when time allows; latest from the normalized endpoint |
| Clean install fails (lock, Python version) | Run not scored | `uv sync --frozen`, `requires-python>=3.12`, CI from a fresh clone |
| Scoring/batch-size ambiguity | Wrong optimization | Design for the strict case; Discord confirmation |
| Revision deadline missed | Stuck on v1 | Submit v1 on Sat; final revision Sun morning |
| Third-party API terms | Disqualify/ban | Only official/NLOD/company-owned sources; search optional and candidates-only; documented in `SOURCES.md` |

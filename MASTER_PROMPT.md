## 1. Context you must know

**Challenge (Builderr, Round 1, closes 21 Oct 2026; revised commit hashes accepted until 18 Oct 2026):**
- Input: Norwegian organisation numbers (a batch file supplied at run time). Output: **exactly one terminal JSON envelope per input** with company facts, source links, dates, availability states.
- States: `available`, `not_available`, `blocked`, `not_applicable`, `ambiguous`, `failed`. Missing is never zero.
- Every claim needs source URL, retrieval time, reporting period (where relevant), content SHA-256, extraction method, claim span.
- Scoring (two published versions): coverage 35/50 (70% company recall + 30% claim recall vs a pooled reference set), precision/evidence 30, update/refresh 20/12, synthesis 10/12, **UX 5/8 ("find, compare and verify on desktop and mobile")**.
- Qualify: ≥65/100 overall and ≥21/35 coverage. **A single wrong-company publication or fabricated financial value disqualifies.**
- Daily limits: 45 min, 2,000 outbound requests, $10 declared external cost. Clean-machine check: clone at the commit → `uv sync --frozen` → one command.
- Board (5 Oct): 0 qualified entries, top score 60.8. Precision and reliability beat volume.

**Honesty rules (non-negotiable, see `benchmark_plan.md`):** no tuning on official batches, no precomputed or cached answers, no padding claims, abstentions reported, every published number reproducible from `reports/` (generated by `eval/write_docs.py`), hand-audit every newly accepted website.
